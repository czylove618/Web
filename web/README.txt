==================================================
属性计算器（Web 版）使用说明
版本 v1.21 · 数据版本 2026/10
==================================================

【简介】
纯前端的角色属性计算器，用于计算 5 名角色经过皮肤/点化转换后的
进场属性、附加属性，以及部分角色的首回合回血参考值。
无需安装、无需后端，双击 index.html 即可使用。

--------------------------------------------------
一、界面与输入
--------------------------------------------------
▸ 拖拽手柄 ⠿
   按住可上下拖动，与目标行「交换」位置（非插入）。
   角色顺序会影响转换池累加，调整顺序可能得到不同结果。

▸ 角色顺序
   下拉选择该行的角色（数据来自 init.js 的 roleMap）。

▸ 体/攻/灵/防
   角色的基础属性，单位：万，支持小数。

▸ 皮肤1 / 皮肤2 / 皮肤3
   - 输入即过滤（子串匹配、不区分大小写、200ms 防抖）
   - 下拉最多显示 60 项，可键盘 ↑ ↓ 选择、Enter 确认、Esc 关闭
   - 在输入框上「右键」显示该皮肤的转换规则（源属性 → 目标属性，百分比）
   - 允许输入「空点化」留空
   - 同一角色三个皮肤按 1 → 2 → 3 的顺序依次应用，
     每一步都以「当前属性 + 转换池已有值」为源，顺序影响结果

--------------------------------------------------
二、按钮功能
--------------------------------------------------
📁 选择工作目录
   授权一个文件夹。句柄存入 IndexedDB（键 workspace），
   下次打开自动恢复，但通常需要重新点击授权一次。

导入配置
   - 已授权目录：弹出该目录下 .json 文件列表供选择
   - 未授权或授权失败：打开本地文件选择框

导出配置
   - 已授权目录：询问文件名后写入工作目录
   - 未授权：下载为 config-<时间戳>.json

保存为默认
   - 目录模式：写入 config.json
   - 否则：写入浏览器 localStorage
   运行结束会提示实际保存位置

加载默认
   从默认配置（config.json → localStorage）重新载入表单

重置为初始
   回到内置初始配置（app.js 中的 BUILTIN_DEFAULT）

📷 识别属性
   打开 OCR 识别模态框。截图 → 拖拽框选属性数字 → 识别 →
   手动核对/修正 → 选目标行 → 填入表单。
   详见「六、OCR 截图识别」。

计算
   输出附加属性、进场属性、首回合回血参考。
   皮肤名无效时结果中会标记「皮肤名称"xxx"错误」

清空结果
   仅清空下方结果文本框

查看说明
   打开本说明文档（加载顺序见第七节）

--------------------------------------------------
三、配置优先级与持久化
--------------------------------------------------
默认配置加载顺序：
   1. 工作目录下的 config.json
   2. localStorage（键：pkcal_default_config）
   3. BUILTIN_DEFAULT（app.js 中的兜底配置）

说明：
- config.json 被手动编辑且格式错误时会自动回退到下一层
- 首次选择工作目录、或启动时目录已授权但缺少 config.json，
  会自动生成一份（内容取当前有效默认配置）
- 基准配置单独存在 localStorage（键：pkcal_baseline_config），
  与默认配置互不影响

--------------------------------------------------
四、皮肤优化器
--------------------------------------------------
展开「🔍 皮肤优化器」面板使用。算法为「坐标上升 + 随机重启」：
- 皮肤1（索引 0）固定不参与优化，只搜索皮肤2/3
- 皮肤2/3 从同一候选池中挑选，允许同一互斥组皮肤多次入选

▸ 优化目标
   - total      体/1.5 + 攻 + 灵×1.3（默认）
   - body       体总和
   - attack     攻总和
   - spirit     灵总和
   - weighted   自定义权重（体/攻/灵/防/速）
   注：速 目标仅在配置中产生「速」类转换时有意义

▸ 候选皮肤池
   - 展示 init.js 中 skinIncludeMap 的全部皮肤
   - 默认勾选：来自 app.js 的 DEFAULT_SKIN_NAMES 显式列表（互斥皮肤仅保留一个最大值，忽略五灵属性是否相同）
   - 工具栏：
     · 搜索皮肤名   输入即过滤
     · 全选当前     勾选当前过滤结果
     · 清空当前     取消勾选当前过滤结果
     · 默认勾选     恢复app.js 中的 DEFAULT_SKIN_NAMES默认勾选集合

▸ 维护默认皮肤列表（DEFAULT_SKIN_NAMES）
   位置：app.js → initOptimizerUI() → "候选池"注释块
   方法：
     1. 在页面手动勾选期望的皮肤组合
     2. 控制台执行：
          copy(JSON.stringify(Array.from(selectedSet), null, 4))
     3. 粘贴回 DEFAULT_SKIN_NAMES = [...] 即可

▸ 对比基准
   - 「以当前配置设为基准」保存当前角色顺序与皮肤
   - 「从基准载入表单」把基准写回表单
   - 优化结束后，若基准与当前角色顺序一致，会输出：
     · 基准评分 / 最优评分 / 差异百分比
     · 逐角色的皮肤2/3 差异清单
   - 基准只存在 localStorage，清缓存前请自行记录

▸ 运行参数
   - 最大轮数：每轮坐标上升的最大扫描次数（1~10）
   - 随机重启：从当前配置之外的若干个随机初始状态开始
   - 总超时：所有重启共享的总时间上限（秒）

▸ 运行与输出
   - 日志区实时显示每次改进（角色、皮肤位、由→到、当前评分）
   - 「停止」：立即中断，已获得的最优结果仍可应用
   - 「应用最优结果」：把最优的皮肤2/3 写回表单并自动重新计算

--------------------------------------------------
五、计算规则说明（calc.js）
--------------------------------------------------
1) 角色基础转换（calRole）
   按 init.js 中 roleBaseRule 对每个角色做一轮基础转换，
   源值 = 角色当前属性 + 转换池已有累加值。

2) 皮肤转换（calindition / calculationDouble）
   - 皮肤全称先映射到简化规则名（skinIncludeMap）
   - 乾元类皮肤会同时应用两条规则（qianYuan）
   - 转换源值 = 角色当前属性 + 转换池累加值
   - 目标为攻/灵/防时执行溢出保护：
       上限 MAX_VALUE = (2^31-1) × 5 / 10000 ≈ 1073741.8
   - 目标为「速」时不进入转换池，单独记录并在结果中展示
     （多次转换速时后写覆盖前写）

3) 结果输出
   - 附加属性：转换池中各属性的总和
   - 进场属性：附加属性 + 该角色自身属性
   - 首回合回血参考（仅以下角色）：
       · 归尘紫英 (16) 基于体回血 10%
       · 夏侯夫人 (3)  基于灵回血 60%
       · 魔化玄霄 (20) 基于灵回血 50%
     若场上只有一名「灵回血」角色，额外输出其普攻回血：
       普攻回血 = (该角色进场体属性 + 开局回血之和) × 普攻比例
     普攻比例：夏侯夫人 50%、魔化玄霄 35%

--------------------------------------------------
六、OCR 截图识别
--------------------------------------------------
▸ 用途
  从游戏内属性面板截图中识别 体/攻/灵/防 数值，
  自动换算成「万」并填入目标行。

▸ 打开方式
   点击页面顶部「📷 识别属性」按钮。

▸ 加载图片（三种方式）
   - 点击「选择图片」
   - 在模态框内 Ctrl+V 粘贴
   - 拖拽图片文件到模态框

▸ 框选与编辑
   图片显示后，在图上拖拽即可创建选区（最多 4 个）。
   选区支持完整编辑：
     · 单击已有选区           → 选中（边框变黄、出现 8 个控制点）
     · 拖拽选区内部           → 移动位置
     · 拖拽 8 个控制点        → 调整大小
     · 选中状态按 Delete      → 删除该选区
     · 选中状态按 Esc         → 取消选中
     · 未选中状态按 Esc       → 关闭模态框
     · 点击空白区域           → 取消选中
   任何选区变化（画/移/调/删）都会自动作废已有识别结果，
   避免把旧数值填错行。

▸ 识别
   - 点击「识别选区」：
       首次需从 CDN 下载 Tesseract 引擎 + 英文语言包（约 10MB），
       耗时约 10~20 秒；之后复用 worker，秒出结果。
   - 识别使用「数字白名单」模式，只识别 0-9 与小数点，
     不识别中文，因此精度更高、包更小。
   - 每个选区如果含多个数字（如一段区域里识别出 4 个），
     会全部进结果表。

▸ 单位换算
   - 识别原值为「个位」（如 146554572）
   - 强制 ÷10000 换算成「万」（如 14655.4572）
   - 结果表同时显示两列：
       · 原值（识别）  ——  只读，用于核对有没有漏位
       · 换算值（万）  ——  可编辑，这个值才是被填入表单的
   - 原值位数不在 7~10 位之间时，原值列会标红提示
     （常用于发现 OCR 漏识/多识的问题）

▸ 填入表单
   1. 在结果表中核对每一行：
        · 若识别有误，直接改「换算值」输入框
        · 用右侧下拉选择这个数字应填入的属性（体/攻/灵/防）
   2. 在「填入到」下拉选择目标行（显示第 N 行 · 角色名）
   3. 点击「填入表单」
   注意：同一属性多次出现时只取第一次出现的值，
        其余行需自行修改属性下拉以避免冲突。

▸ 兼容性要点
   - OCR 功能首次使用需要联网下载 Tesseract 资源
   - 完全离线部署时，需把 tesseract.min.js、wasm、traineddata
     放本地并用 HTTP 服务器托管（file:// 下 wasm 会被 CORS 拦截）
   - Tesseract 未加载时，「识别属性」按钮会自动禁用并提示

八、浏览器兼容性

- Firefox / Safari：无法使用工作目录，

九、项目结构
--------------------------------------------------
index.html   页面骨架、按钮、模态框、脚本引入顺序
style.css    全部样式（表格、下拉、模态框、优化器、tooltip）
init.js      静态数据（新增皮肤 / 改比例 / 加角色在此修改）
              ├─ conversionMap   皮肤简化名 → [源,目标,比例,分类]
              ├─ roleMap         角色 ID → 角色名
              ├─ skinIncludeMap  皮肤全称 → 简化规则名
              ├─ qianYuan        乾元皮肤 → 双规则名
              ├─ roleBaseRule    角色 → 基础转换规则
              ├─ VERSION / DATA  版本号与数据版本
              └─ ATTR_NAMES      属性名数组
calc.js      计算逻辑
              ├─ calculate()          主入口，返回带格式文本
              ├─ evaluate()           精简接口，供优化器调用
              ├─ calRole()            角色基础转换
              ├─ calindition()        皮肤转换
              ├─ calculationDouble()  单条规则应用
              ├─ getSum()/getTrueValue()
              ├─ HEAL_RULES           回血规则表
              └─ printFinalResult()   结果输出
fs.js        工作目录封装
              └─ Workspace   授权、读写、IndexedDB 句柄持久化
optimize.js  皮肤优化器
              └─ Optimizer   坐标上升 + 随机重启
app.js       UI 逻辑
              ├─ BUILTIN_DEFAULT      内置默认配置
              ├─ AutoCompleteComboBox 自动补全组件
              ├─ Row / 拖拽排序
              ├─ DefaultConfig        默认配置管理（三层优先级）
              ├─ 导入 / 导出逻辑
              ├─ BaselineConfig       优化器对比基准
              └─ 说明文档加载

十、数据维护（init.js）
--------------------------------------------------
▸ 新增皮肤
   在 initSkin() 的对应分组用 P([...], "规则名") 加入皮肤全称。
▸ 新增乾元皮肤（双规则）
   1. initSkin()  : m.set("乾元XXX", "乾元XXX");
   2. initSkinQ() : q.set("乾元XXX", ["规则A","规则B"]);
▸ 修改转换比例
   修改 initConversionMap() 中对应规则的第 3 个元素（0~1 的小数）。
▸ 新增角色
   - initRoleMap()      : rm.set(id, "角色名")
   - initRoleBaseRule() : r.set(id, [[源,目标,比例,是否封顶], ...])
   - 若需进入首回合回血参考，在 calc.js 的 HEAL_RULES 增加条目
